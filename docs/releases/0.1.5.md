# Flick 0.1.5

Flick 0.1.5 introduces a redesigned, content-first UX/UI inspired by the
clarity of DuckStation and PCSX2 while remaining a focused native image viewer.
The image receives nearly the entire window: there is no permanent toolbar,
sidebar, status bar, or navigation chrome.

## Redesigned viewing experience

- Adds purpose-built Empty, Loading, Displayed, Load error, Large-image
  confirmation, and Drop target states instead of presenting every situation
  through the same canvas or a modal message.
- Opens images fitted to the available viewport and continuously refits them
  when the window changes size. An explicit user zoom remains under user
  control rather than being overwritten by a resize.
- Adds a quiet bottom status overlay for filename, sequence position, zoom,
  rotation, and short command feedback. It appears when useful and fades away
  instead of permanently taking space from the image.
- Makes loading less distracting by delaying the progress indicator for fast
  decodes and cache hits.
- Adds lightweight first-use guidance for browsing, commands, and leaving
  fullscreen without introducing an onboarding wizard.

## Commands, fullscreen, and dialogs

- Organizes commands across native application menus, keyboard shortcuts, and
  a complete grouped context menu. File and context menus share the same
  `Quit` action.
- Makes fullscreen truly content-only by hiding the application menu while
  keeping the context menu available. `Esc` leaves fullscreen, and closing the
  application there no longer makes the next launch fullscreen.
- Adds predictable `Esc` precedence for menus, dialogs, large-image
  confirmation, and fullscreen without using it to close the application.
- Adds a compact transactional Settings dialog with immediate preview,
  Apply, Cancel, and Reset Defaults behavior.
- Adds a non-modal Image Information dialog that stays open and updates while
  browsing, without permanently reducing the viewing area.
- Retains platform-native conventions, shortcuts, dialogs, focus behavior, and
  accessibility semantics on Linux and macOS.

## Reliability and release pipeline

- Strengthens asynchronous decoding, browsing-sequence reconciliation,
  decoded-image caching, and adjacent-image prefetching.
- Expands cross-platform process, architecture, UX, packaging, and performance
  coverage, including deterministic waits for observable UI state.
- Refreshes the verified SHA-256 pins for upstream `linuxdeploy` build 368 and
  Qt deployment plugin build 256 used by the Linux release workflow.

The supported platform baseline remains Linux and macOS 13 or newer.
